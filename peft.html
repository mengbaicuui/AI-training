PEFT 方法概览

为什么需要参数高效微调？

全量微调大模型面临显存不足、训练成本高、容易过拟合等问题。PEFT（Parameter-Efficient Fine-Tuning）通过只训练少量参数来解决这些问题。

对比项 全量微调 PEFT
可训练参数
▶ 100%
所有层参数 全部更新
7B 模型参数量 ~70 亿
需要大量数据防止过拟合
▶ 0.1% ~ 3%
LoRA (r=16) ~0.1%
P-Tuning v2 ~1-3%
少量参数即可学习新任务
7B 模型显存
▶ ~60GB+
模型参数 (FP16) 7B × 2B ≈ 14GB
梯度 (FP16) ≈ 14GB
优化器状态 (Adam) 一阶矩+二阶矩 ≈ 28GB
激活值 / Buffer ≈ 几 GB
👉 14 + 14 + 28 ≈ 56GB → 通常说 ~60GB+
▶ ~6-16GB

基础模型冻结，只需存储 LoRA 参数的梯度和优化器状态：

QLoRA (~6GB) 模型 4-bit 量化 ≈ 4GB
+ LoRA 参数 ≈ 2GB
LoRA (~16GB) 模型 FP16 ≈ 14GB
+ LoRA 参数 ≈ 2GB
👉 省掉了梯度 14GB + 优化器 28GB = 42GB
训练数据需求
▶ 大量数据
推荐数据量 Token 数 ≥ 参数量
7B 模型 数十万~百万条
数据不足容易过拟合
▶ 少量数据即可
最少数据量 几百~几千条
推荐数据量 1万~10万条
参数少，不易过拟合
灾难性遗忘
▶ 风险高

为什么全量微调容易遗忘？

根本原因 所有权重被直接修改
机制 新任务梯度覆盖旧知识
表现 学会领域任务，忘了通用能力
⚠️ 神经网络的"塑性-稳定性困境"：学新的容易忘旧的
▶ 风险低

为什么 LoRA 不容易遗忘？

核心机制 原始权重 W₀ 完全冻结
学习方式 只学增量 ΔW = BA
推理时 W = W₀ + ΔW 合并
✅ 新知识是"加法"而非"覆盖"，旧知识完整保留

主流 PEFT 方法分类

PEFT 方法主要分为三大类，它们的核心思想都是"外挂"少量可训练参数：

▶ 💡 什么是"可训练的虚拟 Token"？点击展开

虚拟 Token（也叫 Soft Prompt）是一组不对应任何真实词汇的 Embedding 向量。它们被添加到输入序列的开头，通过训练学习到"如何引导模型完成特定任务"。

📝 实际训练样本示例
[P₁][P₂][P₃]...[Pₙ] ← 虚拟 Token（可训练）
用户：故障码 P0301 是什么意思？
助手：P0301 表示第1缸失火。可能原因：火花塞损坏、点火线圈故障、喷油嘴堵塞...
训练时
只更新 [P₁]...[Pₙ] 的 Embedding
推理时
虚拟 Token 自动拼接到输入前
⚡ 直觉理解： 虚拟 Token 就像是给模型的一段"隐藏指令"，告诉它"现在你是一个汽修专家"，但这段指令是通过训练自动学出来的，而非人工编写。

各方法详细对比

方法 原理 作用位置 优点 缺点
Prompt Tuning
▶ 在输入层添加可训练的虚拟 Token

在词表外新增 n 个可学习的 Embedding：

输入 = [P₁][P₂]...[Pₙ] + 原始文本
训练时只更新这 n 个 Embedding，模型参数冻结
▶ 第一层 Attention
只作用于 输入 Embedding 层
虚拟 Token 只在最开始拼接一次，后续层不再添加
 参数量极少（~0.01%）
▶ 效果依赖模型规模
10B+ 模型 效果接近全量微调
小模型 (<1B) 效果明显下降
原论文：模型越大，Prompt Tuning 越有效
Prefix Tuning
▶ 在每层都添加可训练的 Prefix

每一层 Transformer 的 K、V 前都拼接可学习向量：

K = [Prefix_K, K_original]
V = [Prefix_V, V_original]
通过 MLP 重参数化来稳定训练
 所有层 Attention 比 Prompt Tuning 效果好
▶ 难训练，挤占序列空间
挤占空间 Prefix 占用 max_length 配额
训练不稳定 需要 MLP 重参数化
如 prefix_len=128，实际输入只剩 max_len-128
P-Tuning v2
▶ Prefix Tuning 优化版

改进点：

移除 MLP 直接优化 Prefix Embedding
多任务学习 共享部分 Prefix
清华提出，ChatGLM 系列采用此方法
 所有层 Attention 接近全量微调效果
▶ 容易导致旧知识遗忘

为什么 P-Tuning v2 会遗忘？

影响范围 每层 Attention 都被改变
vs LoRA LoRA 原始权重完全冻结
⚠️ 如需保留通用能力，优先选 LoRA
Adapter
▶ 在 Transformer 层间插入小型 MLP

Adapter 结构：

h → Down(h) → ReLU → Up(h) → h + residual
Down 投影 d → r (降维)
Up 投影 r → d (升维)
每层之后 效果稳定
▶ 增加推理延迟

为什么会增加延迟？

原因 新增了串行计算层
vs LoRA LoRA 可合并，无额外计算
每次前向传播都要过 Adapter，无法融合
LoRA
▶ 低秩矩阵近似权重更新

核心公式：

W = W₀ + B × A
W₀ 原始权重，冻结
B, A 低秩矩阵，可训练
推理时 BA 合并到 W₀，零延迟
▶ Attention 的 Q/K/V/O

常见配置：

原论文 只加 Q, V
实践推荐 Q, K, V, O 都加
进阶 也可加 FFN 的 gate/up/down
无推理延迟，抗遗忘
▶ 需要选择合适的 Rank

Rank 选择指南：

简单任务 r = 4 ~ 8
复杂/垂域任务 r = 16 ~ 64
Rank 越大参数越多，需权衡效果与成本
🏆
推荐选择：综合考虑效果、推理延迟和抗遗忘能力，LoRA 是目前最主流的选择。它在 GPT-3 175B 上的实验表明，仅用 0.01% 的可训练参数即可达到全量微调的效果。

LoRA 与 QLoRA 原理及在汽修场景的参数配置

LoRA 核心思想

LoRA（Low-Rank Adaptation）通过低秩分解来近似权重更新，大幅减少可训练参数量。原始权重矩阵保持冻结，仅训练两个小矩阵 B 和 A。

\[ h = W_0 x + \Delta W x = W_0 x + BA x \]
其中 \( B \in \mathbb{R}^{d \times r} \)，\( A \in \mathbb{R}^{r \times k} \)，\( r \ll \min(d, k) \)
  • 原始权重 W₀ 保持冻结，不参与梯度更新
  • 只训练低秩矩阵 B 和 A，参数量从 d×k 降至 (d+k)×r
  • 推理时可将 BA 合并到 W₀，无额外延迟

QLoRA：更省显存的方案

QLoRA 在 LoRA 基础上引入 4-bit 量化，使得在消费级 GPU 上微调大模型成为可能。

特性 LoRA QLoRA
基础模型精度 FP16 / BF16 NF4 (4-bit)
7B 模型显存 ~14GB ~6GB
训练速度 较快 略慢（需反量化）
适用场景 显存充足 显存受限
💡
NF4 数据类型：专为正态分布权重设计的 4-bit 量化格式，信息损失更小。QLoRA 还采用双重量化（Double Quantization）进一步压缩量化常数的存储。

参数配置指南（Rank, Alpha）

参数 含义 推荐值 说明
r (Rank) 低秩矩阵的秩 8 / 16 / 32 领域差异越大，Rank 越高
lora_alpha 缩放因子 = Rank 或 2×Rank 实际缩放 = alpha / r
target_modules 应用 LoRA 的层 q_proj, v_proj 可扩展到 k, o, gate 等
lora_dropout Dropout 比例 0.05 ~ 0.1 防止过拟合
Python 
from peft import LoraConfig, get_peft_model

peft_config = LoraConfig(
    r=16,                        # Rank: 低秩矩阵的秩
    lora_alpha=32,                # Alpha: 缩放因子
    target_modules=["q_proj", "v_proj"],  # 目标层
    lora_dropout=0.05,            # Dropout
    bias="none",
    task_type="CAUSAL_LM"
)

model = get_peft_model(base_model, peft_config)
model.print_trainable_parameters()
# 输出: trainable params: 4,194,304 || all params: 6,738,415,616 || trainable%: 0.0622%
⚠️
Rank 选择经验：度量模型与垂直领域的差异性。如果目标领域（如汽修）与预训练数据差异较大，建议使用 Rank=16~32；若主要是通用问答，Rank=8 通常足够。

如何避免"灾难性遗忘"

什么是灾难性遗忘？

当模型在新任务（如垂直领域数据）上训练时，可能会"忘记"之前学到的通用能力。这种现象称为灾难性遗忘（Catastrophic Forgetting）。

LoRA 的天然优势

LoRA 冻结原始权重 W₀，只学习增量 ΔW，因此原始能力得以保留。这是 LoRA 相比 P-Tuning v2 等方法的重要优势。

  • 原始权重完全不变，保留预训练知识
  • 增量学习，新旧知识解耦
  • 可通过调整 merge 策略控制融合程度
⚠️
注意：P-Tuning v2 等方法虽然也是参数高效微调，但容易导致旧知识遗忘。如果业务对通用能力有要求，优先选择 LoRA。

额外防护策略

策略 做法 效果
数据混合 训练数据中混入 5-10% 通用数据 保持通用问答能力
Replay 机制 定期在旧任务样本上回顾训练 巩固历史知识
EWC 正则化 对重要参数施加约束，限制更新幅度 保护关键参数
评估监控 训练中定期测试通用能力指标 及时发现遗忘
