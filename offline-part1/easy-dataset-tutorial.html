微调数据准备：用 Easy Dataset 提取 QA 问答对

从领域文档到高质量「问题-答案」微调数据集，三步完成文本分割、问题生成与答案构建，适合课堂演示与动手练习。

1. 微调数据准备与 QA 对

1.1 什么是微调数据准备？

在 SFT（监督微调）阶段，模型需要的是结构化指令数据，最常见的形式就是「指令-回答」或「问题-答案」对。微调数据准备，就是把原始资料（文档、PDF、Markdown 等）整理成模型可学习的 QA 对或指令-回答对。

高质量数据准备直接决定微调效果：数据噪声大、问题与答案不匹配、格式不统一，都会拉低模型表现。

1.2 为什么需要 QA 对？

  • 对齐任务分布：让模型在「问-答」分布上学习，更符合实际使用场景。
  • 知识可检验：问题明确、答案可对照原文，便于做质量审核与抽样检查。
  • 格式统一：便于导出为 Alpaca、ShareGPT、JSONL 等标准格式，直接用于 LLaMA Factory 等训练框架。

2. Easy Dataset 简介

2.1 是什么？

Easy Dataset 是面向大语言模型微调的数据集构建工具，由 ConardLi 开源维护。它提供可视化界面，内置文档解析、智能分段、问题生成与答案生成，能把 PDF、Markdown、DOCX、TXT 等格式的领域文档，转成可直接用于微调的 QA 数据集。

适合在课堂上演示「从文档到数据集」的完整流水线，学生无需写代码即可完成一次完整的微调数据准备。

2.2 核心能力（与 QA 对相关）

📄 多格式文档解析
支持 PDF、Markdown、DOCX、TXT、EPUB 等，自动识别结构。
✂️ 智能文本分割
按 Markdown 结构、递归分隔符、固定长度或代码块等策略切分。
❓ 自动问题生成
基于文本片段生成相关问题，支持模板与批量生成。
💬 答案生成与编辑
调用 LLM API 生成答案，支持人工编辑与系统提示自定义。

导出格式支持 Alpaca、ShareGPT、JSON/JSONL 等，可与 LLaMA Factory 等工具无缝对接。

ℹ️
项目地址：GitHub - ConardLi/easy-dataset； 文档与演示视频见官方 docs.easy-dataset.com。

3. 三步生成 QA 数据集

3.1 整体流程

用 Easy Dataset 从文档提取 QA 对，本质是三条流水线：文本分割 → 问题生成 → 答案构建。

1. 文本分割 → 2. 问题生成 → 3. 答案构建

每一步都在界面里完成，可随时调整分段策略、问题模板和模型参数，适合课堂分步演示。

3.2 第一步：文本分割

把整篇文档切成若干「片段」（chunk），每个片段对应后续的 1 个或多个问题。分割方式影响问题的粒度和上下文长度。

  • 按 Markdown 结构：按标题、列表等切分，适合讲义、文档类。
  • 递归分隔符：按段落、换行等递归切，可设最小/最大长度。
  • 固定长度：按字符或 token 数切块，需注意不要切断句子。

课堂演示建议：先用一篇短 Markdown（如课程说明或规章摘要），选「Markdown 结构」分割，便于学生观察「一段文本 → 一个片段」的对应关系。

3.3 第二步：问题生成

针对每个文本片段，由模型或规则生成若干问题。问题应能由该片段内容回答，避免跨段或过于泛化。

  • 可使用内置的问题生成模板，或自定义 prompt。
  • 支持批量生成，生成后可逐条编辑、删除或补充。

演示时可强调：问题质量直接影响后续答案和微调效果，可抽样检查「问题是否能在原文中找到依据」。

3.4 第三步：答案构建

为每个问题生成答案。Easy Dataset 通过配置好的 LLM API（如 OpenAI 兼容接口、智谱、通义等）调用模型，以「问题 + 对应文本片段」为上下文生成答案。

  • 可设置系统提示（如「你是一名助教，请根据以下资料简洁回答」），统一风格。
  • 生成后可人工编辑，修正事实错误或冗长表述。

最终得到的是标准的「问题-答案」对，并可关联回原文片段，便于质检。

4. 安装与快速开始（课堂演示用）

4.1 方式一：直接下载客户端（推荐演示）

从 GitHub Releases 下载对应系统的安装包（Windows 的 Setup.exe、macOS 的 .dmg、Linux 的 AppImage），安装后本地运行，无需配置 Node 环境，适合教室电脑或学生自带笔记本。

4.2 方式二：NPM 本地运行

bash
git clone https://github.com/ConardLi/easy-dataset.git
cd easy-dataset
npm install
npm run build
npm run start

启动后浏览器访问 http://localhost:1717。

4.3 方式三：Docker

docker-compose.yml 示例
services:
  easy-dataset:
    image: ghcr.io/conardli/easy-dataset
    container_name: easy-dataset
    ports:
      - '1717:1717'
    volumes:
      - ./local-db:/app/local-db
      - ./prisma:/app/prisma
    restart: unless-stopped

执行 docker-compose up -d 后访问 http://localhost:1717。

⚠️
API 配置：问题生成与答案生成会调用 LLM API，需在 Easy Dataset 内配置 API Key 和 base URL（如使用 OpenAI 兼容接口、智谱、Ollama 等）。课堂演示可先用本地 Ollama 或学校提供的接口，避免外网与计费问题。

5. 课堂演示步骤小结

建议的演示顺序

准备材料：一篇短 Markdown（如课程大纲、某章小结），或先用 MinerU 等工具把 PDF 转成 Markdown。
创建项目：在 Easy Dataset 中新建项目，上传/粘贴该 Markdown。
文本分割：选择「Markdown 结构」或「递归分隔符」，预览分段结果，必要时微调参数。
问题生成：对每个片段批量生成问题，展示 1～2 条编辑与删除操作。
答案生成：配置好 API 后批量生成答案，展示如何根据原文做人工修正。
导出：导出为 Alpaca 或 ShareGPT 格式的 JSONL，用一两行示例说明如何用于 LLaMA Factory 等微调。
✅
课后练习建议：让学生用同一份文档自行走通三步，并导出一份 JSONL；或分组完成「分段 → 出题 → 写答案」中不同步骤，再合并为一份数据集，加深对数据流水线的理解。

6. 输出格式与后续使用

6.1 常见导出格式

格式 说明 典型用途
Alpaca instruction / input / output 字段 LLaMA Factory 等单轮指令微调
ShareGPT 多轮 conversations 列表 LLaMA Factory 等多轮对话微调
JSON / JSONL 每行一条样本，字段可自定义 通用格式，可转为 Alpaca/ShareGPT 等

6.2 格式长什么样？（示例）

LLaMA Factory 等框架常用 Alpaca 与 ShareGPT，导出为 JSONL（每行一条 JSON）。

Alpaca 格式：单条样本包含 instruction、input（可选）、output。

Alpaca 单条示例（JSONL 一行）
{"instruction": "什么是监督微调？", "input": "", "output": "监督微调（SFT）是在预训练模型基础上，用指令-回答对数据进行有监督训练，使模型学会遵循指令并生成高质量回答。"}

ShareGPT 格式：单条样本包含 conversations 列表，每项有 from（human/user、gpt/assistant）和 value，适合多轮对话。

ShareGPT 单条示例（JSONL 一行）
{"conversations": [{"from": "human", "value": "什么是 SFT？"}, {"from": "gpt", "value": "SFT 即监督微调，用指令-回答对训练模型。"}]}

Easy Dataset 导出时选择对应格式即可得到上述结构的 JSONL，直接用于 LLaMA Factory 的数据集配置。

6.3 与微调流程的衔接

导出的 JSONL 可直接作为 LLaMA Factory、Xtuner 等工具的「微调数据集」路径。在课程中可简要说明：同一份 QA 数据既可做 SFT，也可在做 RAG 时作为「检索到的文档 + 标准问答」的评估集。
