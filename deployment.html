推理部署工程化最佳实践

使用 vLLM 或 TGI 构建高并发推理服务

使用 vLLM 或 TGI 进行高并发部署

生产环境部署大模型推理服务，需要考虑吞吐量、延迟和资源利用率。目前主流的两个推理框架是 vLLM 和 TGI（Text Generation Inference）。

⚡
vLLM 高吞吐
  • ✅ PagedAttention 显存高效管理
  • ✅ Continuous Batching 动态批处理
  • ✅ 吞吐量领先，适合高并发
  • ✅ 支持多种模型架构
  • ⚠️ 需要一定配置工作
🤗
TGI 易部署
  • ✅ HuggingFace 官方出品
  • ✅ Docker 一键部署
  • ✅ 与 HF 生态无缝集成
  • ✅ 内置 Web UI 和 API
  • ⚠️ 吞吐量略低于 vLLM
对比项 vLLM TGI
吞吐量 更高（PagedAttention） 较高
部署复杂度 中等，需要配置 简单，Docker 即用
模型支持 主流 LLM HF Hub 模型
社区活跃度 非常活跃 HF 官方维护
推荐场景 追求极致性能 快速上线、原型验证

vLLM 核心技术：PagedAttention

传统推理需要为每个请求预分配连续的 KV Cache 空间，造成显存碎片和浪费。PagedAttention 借鉴操作系统的虚拟内存思想，将 KV Cache 分页管理。

PagedAttention 显存管理示意

💡
性能提升：PagedAttention 可将显存利用率提升至接近 100%，吞吐量相比传统方式提升 2-4 倍，尤其在高并发场景效果显著。

代码示例

vLLM 部署：

Python 
from vllm import LLM, SamplingParams

# 加载模型
llm = LLM(
    model="your-model-path",
    tensor_parallel_size=1,     # GPU 数量
    gpu_memory_utilization=0.9  # 显存利用率
)

# 推理参数
sampling_params = SamplingParams(
    temperature=0.7,
    max_tokens=512
)

# 批量推理
prompts = ["问题1...", "问题2..."]
outputs = llm.generate(prompts, sampling_params)

TGI Docker 部署：

Bash 
# 拉取镜像并启动
docker run --gpus all --shm-size 1g -p 8080:80 \
    -v /path/to/model:/data \
    ghcr.io/huggingface/text-generation-inference:latest \
    --model-id /data \
    --max-input-length 2048 \
    --max-total-tokens 4096

# 调用 API
curl localhost:8080/generate \
    -X POST \
    -H 'Content-Type: application/json' \
    -d '{"inputs": "你的问题", "parameters": {"max_new_tokens": 512}}'
