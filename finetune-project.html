微调项目实战

从数据准备到训练、评估与导出，串联 Easy Dataset 与 LLaMA Factory，完成一次完整的领域微调项目。

1. 项目目标与流程

1.1 目标

选定一个领域（如内部规范、产品文档、客服话术），完成：数据准备 → 注册数据集 → 在 LLaMA Factory 中训练 → 对话测试 → 导出部署。重点体会数据格式、数据质量与微调效果的关系。

1.2 整体流程

领域文档 → Easy Dataset（QA 对） → LLaMA Factory 训练 → 评估与对话 → 导出部署

2. 数据准备（与 Easy Dataset 衔接）

2.1 准备材料

用 Markdown、PDF（可先用 MinerU 等转 Markdown）或已有文档，在 Easy Dataset 中完成：文本分割 → 问题生成 → 答案生成，导出为 Alpaca 或 ShareGPT 格式的 JSONL。

2.2 数据质量检查

  • 抽样检查：问题是否能在原文中找到依据，答案是否与问题匹配。
  • 格式检查：字段名与 LLaMA Factory 的 dataset_info 中 columns 一致（instruction/input/output 或 conversations）。
  • 规模：课堂演示可用几百条；正式项目按领域与资源调整，建议至少数千条并做 train/val 划分。

3. 训练配置与启动

3.1 注册数据集

将导出的 JSONL 放到 LLaMA Factory 的 data/ 目录，在 data/dataset_info.json 中注册数据集名称、file_name、formatting（alpaca/sharegpt）和 columns。

3.2 选择模型与微调方式

选择基座模型路径（如 Qwen2-7B、ChatGLM3-6B）。显存紧张时用 QLoRA（4bit 量化 + LoRA），否则可用 LoRA。设置学习率（如 1e-4 或 5e-5）、batch size、max steps，启动训练。

3.3 监控与保存

在 Web UI 中观察 loss 曲线；可按步数保存 checkpoint，便于后续选最佳 checkpoint 做评估与导出。

4. 评估与对话测试

4.1 评估

在 LLaMA Factory 的「评估」页加载微调后的 adapter，在验证集上查看困惑度等指标，对比不同 step 的 checkpoint。

4.2 对话测试

在「对话」页加载基座 + adapter，用领域内问题做人工测试：指令遵循、事实一致性、风格是否符合预期。根据结果决定是否增加数据、调整学习率或步数后重新训练。

5. 导出与后续部署

5.1 合并与量化

在「导出」页将 LoRA 合并回基座，得到完整权重；可选 4bit/8bit 量化以减小体积与显存，或导出为 GGUF 等格式供 Ollama、vLLM 等使用。

5.2 与业务对接

将导出后的模型接入推理服务或 API，完成从「数据 → 训练 → 部署」的闭环。后续可迭代：补充数据、修正 badcase、增量微调。

6. 常见问题与检查清单

6.1 常见问题

  • 显存不足：减小 batch size、用 QLoRA、缩短 max length。
  • Loss 不降或震荡：调低学习率、检查数据格式与字段是否错位。
  • 对话效果差：检查数据质量与规模，增加领域样本或做多轮对话格式（ShareGPT）。

6.2 实战检查清单

  • JSONL 为 Alpaca 或 ShareGPT 格式，字段名与 dataset_info 一致
  • dataset_info.json 中已注册数据集，file_name 路径正确
  • 基座模型路径正确，显存满足 LoRA/QLoRA 需求
  • 训练后在对话页验证指令与领域表现，再导出
