微调工具使用指南：LLaMA Factory

以 LLaMA Factory 为主线，覆盖数据准备、训练、评估、对话与导出；并简要介绍 Unsloth、ms-SWIFT、ColossalAI 等主流微调工具与 LoRA/QLoRA、软硬件环境、EvalScope 评估。

1. LLaMA Factory 简介（主讲）

1.1 是什么？

LLaMA Factory 是一个统一且高效的微调框架，旨在为超过 100 种大型语言模型（LLMs）和视觉语言模型（VLMs）提供便捷的微调支持，用户能够灵活地定制模型以适应各种下游任务。

1.2 核心能力与特点

📂 广泛模型支持
支持 100+ LLMs 与 VLMs，包括 Llama 3、GLM-4、Mistral Small、PaliGemma2、Qwen、ChatGLM 等最新版本。
⚡ 高效微调方法
集成 LoRA、QLoRA 等，提高训练速度并减少显存占用；支持全参微调与多卡分布式。
🎛️ Web UI 与 API
训练、评估、对话、导出四大模块；提供类似 OpenAI 的 API、Gradio UI 和命令行，可结合 vLLM worker 做推理。
📊 多模态与实验监控
除文本外支持语音识别、音频理解等；实验监控支持 LlamaBoard、TensorBoard、Wandb、MLflow。

数据格式支持 Alpaca、ShareGPT 等，通过 dataset_info.json 注册数据集，与 Easy Dataset 导出的 JSONL 无缝对接。

ℹ️
官方资源：GitHub - LLaMA-Factory； 文档 llamafactory.readthedocs.io。

2. 其他主流微调工具简介

除 LLaMA Factory 外，入门时还可关注以下四类高封装工具：Unsloth、ms-SWIFT、ColossalAI。也可使用更底层库如 PEFT、transformers 等实现高效微调。

2.1 Unsloth

专为 LLM 设计的动态量化与微调框架，通过手写 GPU 内核与数学优化，在无需改硬件的前提下显著加快训练、减少显存。与 HuggingFace 生态兼容，可与 transformers、peft、trl 结合做 SFT 与 DPO，仅需改模型加载方式。

  • 特点：微调速度约 2～5 倍提升、显存占用减少约 80%；4bit 动态量化（如 Qwen3 4bit 仅损失约 1% 性能），适合个人机与单卡。注意：动态量化模型仅支持单卡，无法多卡并行扩大吞吐。
  • 适用：显存有限、希望快速跑通微调或 Colab/Kaggle 免费试用的场景。

GitHub - unslothai/unsloth

2.2 ms-SWIFT（ModelScope）

魔搭社区的轻量级微调与部署框架，一站式覆盖训练、推理、评测、量化与部署。支持 450+ LLMs、150+ 多模态模型（如 Qwen2.5、InternLM3、GLM4、Llama3.3、DeepSeek-R1、Qwen2.5-VL 等）。

  • 特点：集成 LoRA、QLoRA、DoRA、GaLore、UnSloth 等多种轻量方法；支持 DDP、DeepSpeed ZeRO、FSDP 等分布式；推理端支持 vLLM、LMDeploy；提供 Gradio Web UI 做训练与量化。
  • 适用：需要多模型、多模态或与魔搭数据集/模型仓库深度结合的场景。

GitHub - modelscope/swift

2.3 ColossalAI

分布式 AI 训练系统，侧重大规模预训练与超高维并行，提供自动并行、内存优化、流水线/张量并行等。与 Megatron-LM 相比，可用更少 GPU 完成同等规模训练；目前唯一支持 DeepSeek R1 非量化模型高效微调的框架（如 4 节点 8 卡 A100 即可微调）。

  • 适用：企业级多卡/多节点、超大模型或 DeepSeek R1 等特定模型的高效微调。

GitHub - hpcaitech/ColossalAI

3. 微调基础概念速览

微调可分为全量微调（更新全部参数，算力大、改造彻底）与高效微调（只训练部分参数，显存与算力更省）。当前大模型场景下主流高效微调方法为 LoRA 与 QLoRA。

3.1 LoRA 与 QLoRA 简要对比

特性LoRAQLoRA
核心技术低秩适配器（Low-Rank Adapters）低秩适配器 + 量化（INT4/INT8）
适用场景显存受限但设备性能尚可极限显存受限或需快速推理
显存/计算较低，参数少显著降低显存，适合更小设备
训练复杂度较简单，多数场景适用需量化和适配，适合超大模型

3.2 高效微调的典型应用场景

  • 对话风格微调：客服、虚拟助理的语气、礼貌程度与回答方式。
  • 知识灌注：法律、医疗等领域的专有知识与术语。
  • 推理能力提升：长文本理解、多步推理与逻辑关系。
  • Agent 能力（Function calling / MCP）：工具调用、API 与参数解析。

4. 安装与启动（LLaMA Factory）

4.1 环境与安装

需要 Python 3.8+、CUDA（GPU 训练）。推荐使用 conda/venv 创建虚拟环境后安装依赖。

bash
git clone https://github.com/hiyouga/LLaMA-Factory.git
cd LLaMA-Factory
pip install -e ".[torch,metrics]"

将基座模型（如 Qwen2-7B、Qwen3-8B）下载到本地或指定路径，在 Web UI 或配置中填写模型路径。

4.2 启动 Web UI

bash
llamafactory-cli webui

浏览器访问默认地址（如 http://localhost:7860），即可使用训练、评估、对话、导出四个页签。

5. 数据准备

5.1 支持的数据格式

与前面「Easy Dataset」教程衔接：导出的 Alpaca 或 ShareGPT 格式 JSONL，可直接给 LLaMA Factory 使用。训练时框架会通过 tokenizer.apply_chat_template() 将 instruction/input/output 转为模型所需的特殊标记（如 <|im_start|>、user、assistant、<|im_end|> 等）。

格式 用途 关键字段
Alpaca 单轮指令微调 instruction、input（可选）、output
ShareGPT 多轮对话微调 conversations（from + value）

扩展格式：若需系统提示词，可在数据中增加 system 或 instruction 作为系统角色；若做 Function calling 微调，需在 output 中提供符合模型约定的 tool_call 格式（如 <tool_call>{"name": "...", "arguments": {...}}</tool_call>）；若做思考链（如 Qwen3 混合推理），可在 output 中保留思考链标记（如 <think>...</think>），训练时模型会学习「assistant 前的内容 → assistant 后的输出」。

5.2 dataset_info.json 配置详细解答

dataset_info.json 用于注册所有本地与在线数据集；使用自定义数据集时，必须在该文件中添加数据集定义。文件默认放在 dataset_dir 目录（未配置时为 ./data）。

5.2.1 基本配置结构

每个数据集以「数据集名称」为 key，value 为配置对象，常用字段如下：

字段必填说明
file_name本地时必填本地文件名或相对路径（如 my_qa.jsonl、subdir/data.jsonl），相对 data/。
formatting否数据格式，默认 alpaca；可选 sharegpt。
columns否列名映射：框架内部名 → 你 JSON 里的列名（见下表）。
split否使用的数据划分，默认 train。
ranking否是否为偏好数据（DPO/ORPO 等），默认 false。
num_samples否仅使用前 N 条样本（调试用）。

5.2.2 数据源优先级（二选一或组合）

数据可从本地或远程加载，优先级从高到低：

  • hf_hub_url：Hugging Face Hub 上的数据集名
  • ms_hub_url：ModelScope Hub 上的数据集名
  • script_url：包含数据集加载脚本的目录
  • cloud_file_name：S3/GCS 等云存储路径
  • file_name：本地文件/目录（上述都未指定时必填）

本地使用时只需填 file_name，将 JSON/JSONL 等放在 data/ 下即可。

5.2.3 columns 字段映射详解

columns 用于把「你数据里的列名」映射到 LLaMA Factory 内部使用的名字。不写 columns 时，框架默认你的列名就是 instruction / input / output（Alpaca）或 conversations（ShareGPT）。若你的列名不同，必须用 columns 指明对应关系。

框架内部名Alpaca 默认列名说明
promptinstruction人类指令（必填）
queryinput人类输入（选填，与 instruction 拼接成最终用户输入）
responseoutput模型回答（SFT 必填）
systemsystem系统提示词（选填）
historyhistory多轮历史，列表 of [指令, 回答]（选填）
messagesconversationsShareGPT 格式：消息列表，每项 from+value
chosenchosen偏好数据：更好的一侧回答
rejectedrejected偏好数据：更差的一侧回答
images / videos / audios—多模态：媒体路径列表，与文本中 <image>/<video>/<audio> 数量一致

示例：若你的 JSONL 列名是 question、answer，可写 "columns": {"prompt": "question", "response": "answer"}，并保证数据里没有 input 或把 query 映射到空列名/对应列。

5.2.4 formatting 与任务类型

  • alpaca（默认）：单条为 instruction / input / output，可选 system、history。适用于 SFT、预训练（仅 text）、偏好（chosen/rejected）、KTO、多模态（+ images/videos/audios）。
  • sharegpt：单条为 conversations 列表，每项 from（如 human/gpt/function/observation）、value；可选 system、tools。适用于多轮对话、Function calling、OpenAI 风格（可配合 tags 映射 role/content）。

5.2.5 常用配置示例

SFT · Alpaca（列名为默认 instruction/input/output）
"my_qa": {
  "file_name": "my_qa.jsonl",
  "formatting": "alpaca"
}
SFT · Alpaca（自定义列名 → 用 columns 映射）
"my_qa": {
  "file_name": "my_qa.jsonl",
  "formatting": "alpaca",
  "columns": {
    "prompt": "instruction",
    "query": "input",
    "response": "output",
    "system": "system",
    "history": "history"
  }
}
SFT · ShareGPT（多轮对话）
"my_chat": {
  "file_name": "my_chat.jsonl",
  "formatting": "sharegpt",
  "columns": {
    "messages": "conversations",
    "system": "system",
    "tools": "tools"
  }
}
预训练（仅 text 列）
"pretrain": {
  "file_name": "corpus.jsonl",
  "columns": { "prompt": "text" }
}
偏好训练 DPO/ORPO（ranking: true）
"dpo_data": {
  "file_name": "dpo.jsonl",
  "formatting": "alpaca",
  "ranking": true,
  "columns": {
    "prompt": "instruction",
    "query": "input",
    "chosen": "chosen",
    "rejected": "rejected"
  }
}

支持的文件类型：JSON、JSONL、CSV、Parquet、Arrow。将文件放在 data/（或 file_name 指定的子目录），在 Web UI「训练」页选择对应数据集名称即可。

6. Web UI 四大模块

6.1 训练（Train）

选择基座模型路径、数据集、微调方法（推荐 LoRA/QLoRA）。设置学习率（如 1e-4）、batch size、梯度累积、max steps 等。支持 fp16/bf16。点击开始后可在界面查看 loss 曲线与日志。

6.2 评估（Evaluate）

加载微调后的 adapter 或合并后的模型，在验证集上评估困惑度等指标，便于对比不同 checkpoint。

6.3 对话（Chat）

加载基座模型 + 微调权重，在对话页进行人工测试，快速验证指令遵循与领域表现。

6.4 导出（Export）

将 LoRA 合并回基座、量化（如 4bit/8bit）或导出为 GGUF 等格式，便于部署到 vLLM、Ollama 等推理服务。

训练 → 评估 → 对话 → 导出

7. 训练配置要点

7.1 显存与效率

  • LoRA/QLoRA：显存紧张时优先用 QLoRA（4bit 量化基座），rank 常用 8～64。
  • Batch size：单卡可设 1～2，配合梯度累积达到等效大 batch。
  • 序列长度：按数据最大长度设置，过长会占显存。

7.2 学习率与步数

SFT 常用学习率 1e-5～5e-5，max steps 或 num_epochs 按数据量调整；可配合 warmup。避免学习率过大导致过拟合或 loss 震荡。

8. 软硬件环境与显存参考

微调需要 Python 3.8+、CUDA（GPU）。多卡微调时推荐 Linux（Ubuntu/CentOS）以更好支持 DeepSpeed、FSDP 等；仅单卡可在 Windows 下运行。以下为不同规模模型的大致显存参考（FP16 全参微调 vs 4bit 量化/QLoRA），实际以 LoRA/QLoRA 为主时显存会明显低于全参。

8.1 显存占用参考（示意）

模型规模FP16 全参微调（约）4bit 量化微调（约）备注
0.6B~1.2 GB~0.5 GB低端 GPU 或 CPU 可跑
1.7B~3.4 GB~1.5 GB入门级部署
4B~8 GB~3.5 GB中等任务
7B～8B~16 GB~7 GB消费级高端 GPU（如 RTX 3090/4090）
14B~28 GB~12 GB单张 RTX 4090 可微调 4bit
32B~65 GB~32 GB需 A100/H100 或多卡

实际显存还与 batch size、序列长度、LoRA rank 等有关。课程中可按自身硬件选择对应规模基座（如 Qwen2-7B、Qwen3-8B、Qwen3-14B 等），仅需更换模型路径，流程一致。

9. 模型评估：EvalScope 简介

微调前后可借助EvalScope（魔搭社区开源）做能力评估与对比，便于判断微调是否带来提升、是否发生灾难性遗忘。

9.1 功能概览

  • 评测基准：内置 MMLU、CMMLU、C-Eval、GSM8K、MATH、HumanEval 等中英文知识、数学、代码评测。
  • 评估模式：单模型评估、两两对比（Pairwise-Baseline / Pairwise-All）。
  • 统一接口：兼容 HuggingFace、本地模型与 API 调用，支持 generate/chat 接口。
  • 性能压测：除能力评测外，支持吞吐量、延迟等部署性能测试。

GitHub - modelscope/evalscope

💡
建议用法：微调前用 EvalScope 跑一轮基线；微调后再跑同一套评测，对比各维度得分与压测指标，判断效果与稳定性。

10. 快速上手步骤小结

10.1 建议顺序

  1. 用 Easy Dataset 准备一份 Alpaca 或 ShareGPT 格式的 JSONL。
  2. 在 data/dataset_info.json 中注册数据集，将 JSONL 放到 data/。
  3. llamafactory-cli webui 启动 Web UI，在「训练」页选择模型、数据集、LoRA，设置学习率与步数后开始训练。
  4. 训练结束后在「对话」页加载 adapter 做人工测试，必要时在「评估」页看指标。
  5. 在「导出」页合并权重或量化，用于后续部署。
